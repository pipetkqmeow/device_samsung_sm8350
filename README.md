# Device tree for the Samsung Galaxy S21 5G (Snapdragon) — SM-G9910 (o1q)

LineageOS 23.2 (Android 16) device tree for the Snapdragon 888 (SM8350 / lahaina)
variant of the Galaxy S21 5G.

The tree was generated from a live SM-G9910 (TGY, One UI 7, G9910ZHSGHZB1)
and is modelled on the official LineageOS `sm7325-common`/`a52sxq` trees —
the same Samsung QGA BSP family (Android 11 launch, kernel 5.4 qgki,
non-A/B, dynamic partitions, One UI vendor).

## Device info

| Item              | Value |
| ----------------- | ----- |
| Model             | SM-G9910 (Galaxy S21 5G, Snapdragon 888) |
| Codename          | `o1q` |
| SoC               | Qualcomm SM8350 (lahaina) |
| Kernel            | 5.4.274-qgki (`vendor/o1q_chn_openx_defconfig`) |
| Architecture      | arm64 + arm |
| A/B               | No (separate `recovery` partition, `boot` header v3) |
| Dynamic partitions| Yes: `system vendor product odm` in `super` (12574523392 bytes) |
| File-based encryption | FBE v2 + metadata encryption (`/metadata`), f2fs userdata |
| Wi-Fi / BT        | Broadcom BCM4375 (dhd driver, loaded by vendor Wi-Fi HAL blob) |
| NFC               | NXP (vendor HIDL `nxp.android.hardware.nfc@1.2-service` blob) |
| Fingerprint       | Ultrasonic under-display (QBT2000, `fingerprint.ko` + `qbt2000_spidev.ko`) |
| First API level   | 30 |

## Layout

Standard LineageOS device tree, merged (no common/variant split):

```
AndroidProducts.mk, lineage_o1q.mk   — product definition
BoardConfig.mk                       — board configuration (sizes from blockdev)
device.mk                            — packages, configs, overlays
proprietary-files.txt                — validated against the live device
extract-files.py / setup-makefiles.py— blob extraction (LineageOS extract-utils)
configs/                             — pulled from the device: media/audio/nfc/wifi/manifest
init/                                — fstab + init rc files
sepolicy/                            — starting point from sm7325-common
modules.load / modules.load.recovery — from the device (/vendor/lib/modules)
```

## Setting up the build

### 1. Source

```bash
mkdir ~/android/lineage && cd ~/android/lineage
repo init -u https://github.com/LineageOS/android.git -b lineage-23.2 \
    -g default,qcom,lahaina
repo sync
```

The `qcom,lahaina` groups pull in `hardware/qcom-caf/sm8350/*`,
`device/qcom/sepolicy_vndr/legacy-um`, `vendor/qcom/opensource/*`, etc.

### 2. Device tree + kernel + hardware/samsung

Put this tree in `device/samsung/o1q`:

```bash
git clone <your-fork> device/samsung/o1q
```

The kernel is expected at `kernel/samsung/o1q` (see `BoardConfig.mk`:
`TARGET_KERNEL_SOURCE` / `TARGET_KERNEL_CONFIG := vendor/o1q_chn_openx_defconfig`).

Use the working kernel from this machine (physwizz `G9910-S21-5g` tree,
branch `lineage-23.2` — it already carries the `techpack/datarmnet`
import needed for mobile data):

```bash
git clone --branch lineage-23.2 /path/to/G9910-S21-5g \
    kernel/samsung/o1q
```

Notes:

* `TARGET_KERNEL_ADDITIONAL_FLAGS := CONFIG_BUILD_ARM64_DT_OVERLAY=y`
  mirrors the environment of your `build_kernel.sh`, so the Samsung
  palette DTBO overlays (`o1q_chn_openx_w00_r05..r14`) are built.
* `dtbo.img` is packed in the exact stock palette order by the custom
  `dtboimg.mk` (verified byte-identical against the live dtbo partition;
  the bootloader matches overlays by `qcom,board-id`/`dtbo-hw_rev`, and
  this unit uses r14 at `dtbo_idx=3`).
* `TARGET_DTB_LIST_WILDCARD := vendor/qcom/lahaina*` keeps the kitchen-sink
  qgki defconfig's hisilicon DTBs out of `dtb.img` (recovery image).
* The `techpack/datarmnet` import provides `rmnet_core/ctl/offload/shs`
  required by the stock `modules.load` (mobile data path).
* Keep your APatch/KernelSU defconfigs (`o1q_apatch*`) untouched — the
  ROM build uses `o1q_chn_openx_defconfig`, which is clean of them.
* If clang from the LOS 23.2 toolchain rejects this 5.4 tree, compare
  with `LineageOS/android_kernel_samsung_sm7325` (same qgki base) which
  carries the newer-clang fixes.

### 3. Extract proprietary blobs

With the SM-G9910 attached and booted to the stock ROM (root not required
for `/vendor` reads, `adb root` not necessary):

```bash
cd device/samsung/o1q
./extract-files.py   # blobs land in vendor/samsung/o1q
```

`proprietary-files.txt` was generated by enumerating the actual device, so
extraction from this exact firmware (G9910ZHSGHZB1) should be clean. When
moving to a newer firmware, re-run and fix the list accordingly.

### 4. Build

```bash
source build/envsetup.sh
lunch lineage_o1q-userdebug
mka bacon
```

### 5. Flash

The device is **non-A/B** with a download mode:

1. Flash `recovery.img` (from the build) to the `recovery` partition via
   Heimdall/ODIN (`heimdall flash --RECOVERY recovery.img`), or via
   `fastboot flash recovery` from fastbootd.
2. Boot to recovery, factory reset (data is FBE — mandatory when coming
   from One UI), then sideload the zip:
   `adb sideload lineage-23.2-*-o1q.zip`.

## Bring-up status / known TODOs

This is a **starting point** tree, not a finished port. Expect to iterate:

* **Sepolicy** — `sepolicy/` inherited from sm7325-common, with
  device-specific rules added for o1q: QBT2000 ultrasonic fingerprint
  (`vendor_qbt_device`), Broadcom dhd sysfs (`/sys/wifi` → `sysfs_wifi`,
  `/sys/module/dhd` → `sysfs_ss_writable`, labels match the stock vendor
  policy), `vendor.samsung.hardware.wifi::ISehWifi` hwservice context and
  `ro.vendor.wifi.*` property contexts. The tree builds with SELinux
  **enforcing**; if boot fails during bring-up, uncomment the
  `androidboot.selinux=permissive` line in `BoardConfig.mk`, collect
  denials and fix them vendor-side.
* **NFC** — works with the stock NXP HIDL 1.2 HAL blob as-is: the
  LineageOS 23.2 NFC stack (`packages/modules/Nfc`) talks to HIDL
  `android.hardware.nfc INfc` directly through its Rust HIDL FFI
  (verified in `libnfc-nci/src/rust/hal/ffi/hidl.cc`), and the stock
  service registers the standard `android.hardware.nfc@1.0::INfc
  default` interface (up to 1.2). Shipped: the service blob + its rc +
  VINTF manifest + `libnfc-nxp.conf` / `libnfc-nxp_RF.conf` +
  `libsn100u_fw.so` firmware. No AIDL bridge needed.
* **Camera** — full Samsung unihal blob set (camera.qcom.so +
  camera.unihal.default.so + unihal_*.so + per-sensor bins for
  imx555/imx563/imx374/s5kgw2) is included. The
  `com.samsung.android.camera.unihal` APEX is not packaged; camera HAL
  bring-up usually needs extra work (provider 2.6 + Samsung extensions
  in `hardware/samsung`).
* **Face unlock** — vendor face HAL blobs
  (`vendor.samsung.hardware.biometrics.face@2.0/3.0`) are extracted; an
  AIDL bridge is not wired up yet.
* **Wi-Fi** — Broadcom BCM4375 (dhd): firmware, nvram, CLDB blobs and the
  vendor `android.hardware.wifi@1.0-service` HIDL HAL (+ Samsung
  `vendor.samsung.hardware.wifi@2.0-service` extension) are shipped from
  the stock vendor. `macloader`/`mfgloader` run from `wifi_sec.rc`;
  backlight... Wi-Fi firmware is loaded by the HAL itself via
  `/sys/module/dhd/parameters/`. If the HIDL HAL is ever rejected by the
  framework, build `android.hardware.wifi@1.0-default-service` from
  `hardware/interfaces` with libwifi-hal for bcmdhd instead.
* **Lights** — no light HAL is shipped (screen brightness is handled by
  the AIDL display composer `setDisplayBrightness`), same as the
  sm8350/sm7325 LineageOS trees. The stock
  `vendor.samsung.hardware.light-service` AIDL blob is a known fallback.
* **Power** — `powerhint.json` ships with SD888 CPU tables
  (little 1.8 GHz / mid 2.42 GHz / prime 2.84 GHz, Adreno 660 @ 840 MHz)
  taken from the device sysfs.
* **Fingerprint** — ultrasonic UDFPS: QBT2000 blobs + `vendor_qbt_device`
  sepolicy + `ro.vendor.fingerprint.type=udfps` /
  `sensor_location=540|2137|120` (verify against your panel and adjust in
  `vendor.prop` if the indicator is off).
* **Sensors** — multihal 2.0 with vendor subhals
  (`sensors.ssc.so`, `sensors.grip.so`, `sensors.flicker.so`) + lahaina
  registry JSONs from the device.
* **Audio** — mixer paths/platform info are the device's own files; the
  HIDL audio wrapper (`android.hardware.audio@7.0-impl.samsung-o1q`) wraps
  the vendor `audio.primary.lahaina.so` blob, CS35L40 speaker amp firmware
  included.
